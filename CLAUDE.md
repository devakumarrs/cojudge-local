# CLAUDE.md

My CoJudge content folder under git (public: `devakumarrs/cojudge-local`), plus
a Java + VS Code workflow. Read `README.md` and `scripts/README.md` for how it
works; this file is the rules that aren't obvious from them.

## Never publish CoJudge content

The repo is public. Problem statements, tests, checkers and metadata belong to
CoJudge / the original authors and are git-ignored (see `.gitignore`). Never
un-ignore, `git add -f`, or quote them in commits, PRs, comments or docs. History
was already rewritten with `git filter-repo` once to purge them; don't make that
necessary again. Only `Solution.java` (or `<ClassName>.java`), `Main.java`, my own
notes, `scripts/`, `.vscode/` and the READMEs are published.

## Who owns what

- `problems/<slug>/Solution.java` (or `<ClassName>.java`): mine. Never modify the
  solution of a solved problem (`scripts/bash/list-solved-problems.sh`).
  Unsolved starters may be patched just enough to compile.
- `problems/<slug>/Main.java`: generated by `scripts/py/generate-main.py`
  (package `scripts/py/maingen/`). Fix the generator, not the output, then
  regenerate with `./scripts/bash/init-slugs.sh -f <slug>`.
- Everything else in `problems/` and `courses/`: CoJudge's. Don't edit.
- `.vscode/settings.json`: generated on every F5 from `settings.base.json` by
  `scripts/py/merge-vscode-settings.py`. Edit `settings.base.json` only, and keep
  it plain JSON (no comments or trailing commas). The bare editor (no autocomplete,
  hovers or squiggles) is intentional.

## Scripts

- Bash lives in `scripts/bash/`, Python in `scripts/py/`. Java compiling goes
  through `scripts/bash/compile-problem.sh` (Java 21, debug info), not Python.
- `init-slugs.sh` flags: only `-f` / `--force-main` (regenerate `Main.java`).
  A full `-f` run takes about 6 minutes, so pass slugs when you can.
- `ship-problem.sh` (ctrl+shift+c) commits any number of files, but they must
  all be inside one `problems/<slug>/` folder. It then pushes to `origin main`.
- Generated `Main.java` checks examples with the problem's `Marker.isCorrect`, so
  answers in any order (e.g. `subsets`) pass the same way they do in CoJudge.

## Commits

- One problem per commit: `<slug>` the first time, `improve: <slug>` after.
  Solved status is derived from this, so never mix problem files with other
  changes in one commit.
- Workflow and tooling changes go in separate commits with plain descriptive
  messages.
- Commit or push only when I ask. Never force-push or rewrite history without
  walking me through it step by step first.
- Some of my commits have GitHub commit comments (notes for later). Keep them
  when rewriting history.

## How I like to work

- When I say "just answer", answer and don't touch files.
- Docs: short, simple and accurate. Check claims against the scripts (for
  example, `init-slugs.sh` writes the files first and compiles after) and
  correct my wording if it's wrong.
- For risky or multi-step operations, go one step at a time and confirm each.
